## Reporting a Vulnerability

**НЕ создавайте публичный issue для security уязвимостей.**

Если вы обнаружили security уязвимость, пожалуйста:

1. **НЕ публикуйте её публично**
2. Отправьте email на security@example.com (замените на актуальный)
3. Включите:
   - Описание уязвимости
   - Шаги для воспроизведения
   - Потенциальное влияние
   - Предложенное решение (если есть)

### Response Timeline

- Мы подтвердим получение в течение 48 часов
- Оценим серьёзность и приоритет
- Уведомим о плане исправления
- Выпустим патч и security advisory

## Security Best Practices

### Для разработчиков

#### Backend
- ✅ Всегда используйте параметризованные запросы (EF Core делает это автоматически)
- ✅ Валидируйте все входные данные
- ✅ Используйте Azure Key Vault для секретов
- ✅ Включите HTTPS везде
- ✅ Используйте короткий TTL для JWT токенов
- ✅ Логируйте без PII данных
- ✅ Применяйте rate limiting
- ✅ Регулярно обновляйте зависимости

#### Mobile
- ✅ Не храните секреты в коде
- ✅ Используйте Certificate Pinning для production
- ✅ Шифруйте локальные данные (SQLite)
- ✅ Валидируйте SSL сертификаты
- ✅ Используйте биометрическую аутентификацию для sensitive данных

### Для пользователей

- Используйте strong passwords
- Включите двухфакторную аутентификацию (когда доступно)
- Регулярно обновляйте приложение
- Не делитесь медицинскими данными публично
- Используйте только официальные источники для загрузки приложения

## Known Security Considerations

### Medical Data Privacy

Это приложение обрабатывает чувствительные медицинские данные:

1. **GDPR Compliance:**
   - Получаем явное согласие пользователя
   - Предоставляем возможность экспорта данных
   - Предоставляем возможность удаления данных
   - Храним минимум необходимой информации

2. **Data Encryption:**
   - In-transit: TLS 1.2+
   - At-rest: Azure Storage Encryption
   - Field-level: Для особо чувствительных полей

3. **Access Control:**
   - JWT с коротким lifetime
   - Refresh tokens с secure storage
   - Role-based access (если применимо)

### OpenAI Integration

При отправке данных в OpenAI:
- Удаляем/редактируем PII перед отправкой
- Не отправляем полные медицинские истории
- Логируем только redacted версии запросов
- Соблюдаем OpenAI usage policies

### Third-party Dependencies

Регулярно проверяем зависимости на уязвимости:
```bash
# Backend
dotnet list package --vulnerable

# Mobile
flutter pub outdated
```

## Incident Response Plan

В случае security инцидента:

1. **Немедленно:**
   - Изолировать затронутые системы
   - Собрать логи и evidence
   - Уведомить security team

2. **В течение 24 часов:**
   - Оценить масштаб
   - Уведомить затронутых пользователей (если требуется)
   - Начать remediation

3. **В течение 72 часов:**
   - Выпустить патч
   - Публичное уведомление (если применимо)
   - Post-mortem анализ
